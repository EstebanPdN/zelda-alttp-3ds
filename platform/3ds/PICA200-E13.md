# E13: physical E12 probe failure and menu persistence

E12 implemented the GPU renderer, but both supplied physical Old 3DS dumps
show zero attempted/submitted GPU gameplay frames. The startup color test
returned `color-probe-mismatch`, permanently selecting the CPU for that run.

## Hardware evidence

The two E12 dumps at 08:13:59 and 08:15:05 have valid 22-file FNV manifests.
Their 120 recent samples average 26.45 and 37.22 visual FPS. PPU wall time is
35.92 and 24.83 ms; logic is 1.08 and 0.97 ms. CPU worker spans overlap and
must not be added. These are E12 measurements, not E13 performance claims.

The startup log records 1,652 mismatches and first pixel 0x017f instead of
0x0001. That actual value is the first halfword of the reused RGBA8 upload
buffer. The later saved raw buffer has a correct first pixel and only 820
mismatches. Reading while DMA was still writing is consistent with both
observations, and the code confirms the missing GPU completion fence.

All 820 remaining raw mismatches are in color flags 3, main math enabled,
subscreen backdrop (no halving). Every positive RGB5 component is exactly one
level low. A one-unit lower-bound error at TEV stage 2 reproduces every one
of the 65,536 captured pixels, including every matching pixel.

## GPU changes

`ppu_gpu_c3d.h::PicaC3DWaitIdle` waits on the pinned Citro3D GX queue through
`gxCmdQueueWait`. `C3D_FrameSync` only waits on VBlank counters; it is not a
GPU fence. E13 waits for actual GPU consumption before overwriting the atlas
and vertices, before invalidating/reading transfer output, and before freeing
GPU resources. It removes an unnecessary per-frame VBlank wait.

`ppu_gpu.c::DrawLayers`, `DrawComposition`, and `TransferReadback` explicitly
flush each split command list. With bounded `FrameEnd(GX_CMDLIST_FLUSH)`, a
final split flush does not clean previous command-list chunks. Transfers are
queued after a flushed draw chunk, and results are inspected only after queue
completion and successful cache invalidation. Upload/cache failures propagate.

`ConfigureCompose` restores a bias of one RGBA8 unit for subtractive math at
stage 3, before the final eligible-main selection. Subtraction canceled E12's
encoded-color bias. Exact full subtraction is 8*n and half subtraction is
4*n; adding one does not change their RGB5 result, but protects exact 8*n
boundaries from a one-unit lower interpolation result. Clamped black remains
black. Integer and lower-bound TEV tests both match the independent SNES oracle
for all 65,536 cases. This is evidence for the correction, not a replacement
for the actual console probe.

Both real startup probes remain mandatory: 65,536 color cases and an 89,600
pixel scene using actual tiles, sprites, priority, stencil, windows and math.
No mismatch tolerance or forced GPU override was added. Existing frame-level
fallback rules, New 3DS rendering, and bottom UI geometry are unchanged.

Diagnostics schema 2 records the GX fence, readback cache result, and mismatch
counts for all 16 color bands, alongside actual submitted GPU frames.

## Settings changes

The launcher copies the active ROM profile's INI over the working INI each
boot. E12's menu changed the working INI, but only the FPS toggle copied it
back to the profile. Display/camera changes therefore disappeared at restart
unless an unrelated later FPS toggle happened to save them too.

`second_screen_sdl.c::update_ini` now persists every successfully written and
closed menu update through `Platform3DS_PersistRuntimeSettings`. The redundant
FPS-only call is removed. This covers display mode, edge mode, zoom, turbo and
control settings through the existing common writer. Auto still selects
Original/Standard on first Old boot and Wide/Fixed on first New boot; explicit
values override defaults. Tests run the real writer, profile copier and loader
across three independent processes for each model, preserving unrelated keys.

Physical E13 activation, sustained Old 3DS 60 FPS, color and bottom UI during
real gameplay remain hardware acceptance items. An emulator success does not
establish console timing or pixel correctness.
